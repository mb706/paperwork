# A3: Art direction

**Owner:** one Opus agent. **Writes only to:** `design/art/**` and `pm/reports/A3.md`. Large renders go under `design/art/out/`, which is gitignored; add that rule to `.gitignore`. Only the final mocks and contact sheets are committed.

## Why

The game needs a visual identity with real artistic merit, built from what we can produce headlessly on this host:
- Blender 5.2 scripted renders (Cycles on the CPU, or EEVEE through the wrapper);
- procedural textures and shaders;
- vector graphics (SVG through resvg);
- compositing (ImageMagick, numpy).

No image model is available now. A later iteration may add image-model textures, so the pipeline must leave room for them: for example, Blender materials that can take image textures later, and terrain built from texture layers.

The user's words: come up with "a neat design", find an **appropriate style** with the right **atmosphere** for this game. It is not "make it look like Factorio". The spec currently says "Factorio-like: desaturated, a warm key light, grime" (10 §9.1); treat that as one candidate, not as given. Gameplay readability must stay Factorio-grade:
- the direction of belts and inserters, machine state (working, idle, no input, no power) and the identity of items on belts must all read at a glance at normal zoom;
- the scene must stay legible zoomed out.

## What to do

1. **Explore 3 genuinely different directions.** Example axes:
   - grounded pre-rendered industrial realism;
   - an archival or technical-illustration look: ink line work, mid-century technical-manual or Isotype colour, paper-toned ground;
   - a clean stylised diorama;
   - something better that you think of.

   Think about what *Paperwork* should feel like across its arc: a 1945 research site with tabulators and paper, then mainframes, then datacenters, then a takeoff. Ask whether the look should evolve with the eras, and how. Ask what *information is physical* looks like.
2. **Build a real mock for each direction.** Each mock is a 1920×1080 in-game screenshot at the default zoom, composed from **actual procedurally produced assets**, not paint-overs. It shows:
   - terrain with decoratives and an ore or resource patch;
   - a few slice entities:
     - straight and curved belts carrying matter and information items, at least one inserter, and a crafting machine;
     - a furnace-equivalent, a mining drill, a lab-equivalent, a power pole with a generator, and a chest;
   - the character;
   - one or two item icons in the style;
   - a small sample of UI chrome. The spec keeps Factorio's UI layout, so this is a skin only.

   Use the projection the spec defines (10 §6: an oblique camera, square tiles, heights drawn upward) so the mock is honest about what the engine will render. Also produce a zoomed-out version (about 0.3×) of each to check legibility.
3. **Critique and pick.** Critique each mock honestly against these criteria:
   - readability;
   - atmosphere and fit with the theme;
   - distinctiveness from Factorio;
   - **feasibility at full scale**: about 104 entities with animations, about 220 item icons, 18 terrain tiles, decoratives and UI art, all generated by agents headlessly on this host, so estimate render times;
   - runtime cost: atlas sizes, download size, GPU memory against 10 §6.13;
   - consistency across eras;
   - room for later image-model textures.

   Then **recommend one direction**, possibly refined by what you learned from the others, and iterate on it at least once more so the final mock is as good as you can make it.
4. **Write the style guide.** `design/art/DIRECTION.md` must let other agents produce consistent assets without you. It covers:
   - the palette, with hex values and the matter/information split, and the lighting rig: key, fill and rim, shadow direction and softness;
   - the camera and projection, the pixels per tile at each zoom, and the scale and proportions;
   - materials and their rules; line work, if any;
   - icon style: grid, perspective, stroke, colour rules and the silhouette test;
   - how status is shown: working animation, idle, no power;
   - animation guidelines: frame counts and loops;
   - terrain and decoratives;
   - the UI skin, which keeps Factorio's layout and changes the skin only;
   - the per-era evolution rules, if any;
   - the pipeline: script layout, naming, the render settings that are known to work on this host, and how to batch-render; also what the asset-pipeline WP (10 §9) must build;
   - the "do / don't" list.
5. **Keep the prototype pipeline usable.** The prototype scripts in `design/art/proto/` should be reusable starting points for the asset pipeline, not throwaway code.

## Deliverables

- `design/art/DIRECTION.md`
- `design/art/mocks/`:
  - for each direction: `<direction>-1x.png` and `<direction>-0.3x.png`, plus the final iteration;
  - a contact sheet of the assets you made.
- `design/art/proto/`: generator scripts
- `pm/reports/A3.md`, which names the recommendation and its main risks.

## Budget and quality bar

- Take hours if needed. The user wants "great artistic merit".
- View every image you produce (Read the PNG) and judge it honestly, the way a demanding art director would.
- Mediocre is not done. If a direction fails, say so and say why.
