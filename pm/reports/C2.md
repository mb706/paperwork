# C2: The simulation crates (M0 Sim package)
Status: C2a done; C2b and C2c to come

## Phase C2a: the core

### Summary

The core of the simulation exists, natively tested against the frozen golden set (version 7) wherever no rule is
involved.

- **`det`**: piecewise-linear tables (`det::Piecewise`, `piecewise_linear`: exact breakpoints, constant ends, NaN →
  the first value, one documented evaluation order), and the libm wrappers `exp`, `ln`, `atan` and `hypot` beside
  the existing ones.
- **`sim`** (`game/crates/sim/src/`):
  - `world.rs`: the World (`GLOBALS`, the entity table, the container pool, the slot heap, the chunks, `players[]`,
    stats, work timers, RNG streams, pending worldgen requests) and its derived indexes (the serial index, the
    per-shard serial buckets of §4.8, each chunk's entity list and occupancy grid, the scheduler). Entity
    creation and destruction keep all of them in step: lowest free row, generation `(old mod 1,023) + 1`, the next
    serial, a pool row, an inventory block, and chunk rule and view versions.
  - `chunks.rs` (the modified and generated chunks, sorted; map bounds), `spatial.rs` (box queries by chunk list,
    tile queries by occupancy, strict overlap), `heap.rs` (the slot heap: classes, lowest free block, zeroed
    frees, bars, filters, load validation), `players.rs`, `handle.rs` (handles and the serial index: open
    addressing, fixed hash, backward-shift deletion, no iteration API).
  - `rng.rs`: `fmix32`, `rand`, `splitmix32`, xoshiro128**, stream seeding and the World's saved streams.
  - `sched.rs`: active bitsets iterated in slot order (wakes above the cursor run this pass), wake sequence numbers,
    watch lists with at most four registrations per sleep, stale-node compaction and a full sweep that keep nodes
    within twice the live registrations, wake timers in a 4,096-bucket wheel plus a heap, `forget` for destroyed
    entities, NO_SLEEP.
  - `save.rs`: `sim_save`'s `SaveOutput` (every hashed section, ascending, raw frames, then r), `sim_load`'s
    `LoadInput` with its refusals, the two-pass load (the entity table, then everything named by serial), the
    worldgen-pair check, invariant checks, the full state hash (§4.8); `remap.rs`: §8.3's remapping with the load
    report.
  - `digest.rs`: d_t's preimage (rule 27), the slicer (one shard per tick from per-shard indexes, members sorted by
    (section, key), GATE-r2), the reference enumeration it is tested against, `roll`, `lineage0` and
    `lineage_of`.
  - `tick.rs`: `World::tick`: the preflight, phase 1's seq consumption (with rule 12's watermark records), phase 2's
    wake and work timers, phase 16's d_t and slice; per-phase digests and the D6 NaN scan in simcheck builds.
  - `context.rs`: `SimContext`, the module behind the ABI: `init`, `new_world` (no worldgen yet), `load`, `tick`,
    `set_flags`, `blob_put`, `pending_chunks`, `supply_chunk`, `digest`, `state_hash`, `save`, `meta` and
    `load_report`, with §15.8's call order. Outputs are the envelopes' payloads, the golden traces' format.
  - `testkit.rs`: the D18 harness. `record` runs a module and keeps d_t, r_t and the canonical state per tick
    (every tick for the first 2,000, then every 600 and the last); `Variant::{NoSleep, Reload, Heavy}`; `compare`
    names the first differing tick, section and field, decoded by the generated readers.
  - `presentation.rs`: the event queue with its caps and the historical flag (the tick writes it from C2b on).
  - `hash.rs` (XXH64, one-shot and streaming) and `sha256.rs`.
- **`simtool`**: `hash <save|sections> --protos …` (the full state hash, each section's, the tick, r) and `trace
  <save> <log.pwlog> --protos … [--ticks N] [--full] [--no-sleep] [--check]` (prints `tick d slice r`, the format
  of `digests.txt`).
- **Tests**: unit tests in each module, and one integration binary, `crates/sim/tests/core/` (`golden_core`,
  `world_core`, `harness`, `sched_equivalence`, `alloc_free`, and an ignored `scale` probe). RNG vectors:
  `game/test/rng/vectors.py` (an independent implementation) writes `vectors.txt`.

Run: `cd game && taskset -c 0-15 cargo test -p sim --features simcheck`;
`cargo run --release -p simtool -- hash test/golden/m0/start.save --protos test/golden/m0/protos/prototypes.bin`.

### Decisions and deviations

1. **Work timers are an ordered set; the wheel and heap carry wake timers** (§4.6). Work timers must fire in
   `(due, serial, event, owner)` order and are saved in that order, so `World::timers` is a `BTreeSet` of exactly
   those keys: phase 2 pops the ones due, and saving needs no sort. Wake timers only wake (rule 1), so their order
   is free; they use §4.6's 4,096-bucket wheel and a binary heap for delays of 4,096 ticks or more.
2. **Registration bounds** (§4.6, B1-r1 17): a fifth registration in one sleep is a bug (an assertion, a trap).
   Timer registrations count toward the four. A list is compacted when its stale nodes outnumber its live ones,
   and the pool is swept when its nodes exceed twice the live registrations **plus 64** (the allowance keeps tiny
   pools from sweeping on every wake). `Scheduler::begin_tick` runs before phase 1, so a timer set in phase 1 is
   due no earlier than the next tick.
3. **Which load refusal is which** (§15.8 leaves the split open). `ERR_LOAD_SCHEMA`: whatever a generated decoder
   refuses, including the tables' `not_canonical` and `schema_mismatch`. `ERR_LOAD_FORMAT`: a section newer than
   the build; a missing, repeated or misordered section; an unknown section flagged HASHED; a HASHED flag that
   disagrees with the schema; state that breaks cross-section invariants ("corrupt": a reused serial, a dangling
   or doubly owned `InvRef`, a pool row and an entity that do not name each other, a character serial that an
   entity also has, an entity in a chunk that is not modified, a modified chunk that is not generated, a missing
   surface). The golden model maps every `World.load` exception, missing sections included, to `ERR_LOAD_SCHEMA`;
   no golden case tells the two apart.
4. **A baked save from other worldgen rules continues under this build's** (§4.4; 11 §6.3's sealed upgrade). When
   the save's `(worldgen_version, worldgen_data_hash)` differs from the build's and every chunk is stored, the load
   writes the build's pair into `GLOBALS` and starts a new lineage (`new_lineage` in the report). Without that,
   the world's next save would claim the old rules while holding chunks generated by the new ones, and this build
   would refuse its own save with `ERR_WORLDGEN`. The golden case pins only the status (ok); the model keeps the
   old pair.
5. **Remapping beyond the model's M0 cases** (§8.3: "every field whose type is a prototype id or an item key").
   Filters and ground items follow their items (lost ground items are counted). Tiles, hidden tiles, resources
   and world objects are renumbered. A removed resource or world object goes, counted by tile or by object. A
   removed tile cannot be represented, so the load is refused with `ERR_PROTOS` (§3.6: "prototypes that do not
   match the save and cannot be remapped"). Crafting-queue `parent` links follow their entries, and statistics
   keys of items, fluids and entities are remapped and re-sorted. A table that misses an id the state uses, a new
   id outside the build, two tables for one kind or a name count that differs from the removed ids is `ERR_INPUT`.
   The model's own cases (items, entities, recipes) behave exactly as rule 42 says; the `remap-load` trace
   passes.
6. **Entity creation and chunks.** `create_entity` raises the rule version (wrapping) and the entity view version
   of **every** chunk the footprint touches; the model's rules raise the centre chunk's, which is the same for 1×1
   chests. Every chunk under the footprint must be modified, so C2b's `build` makes a pristine chunk modified
   before it places anything (§4.4: a build modifies a chunk). Creation refuses before changing anything
   (parity, chunks, a full pool), so a refused creation consumes no serial.
7. **Phase 1 in C2a** consumes each action's seq and creates rule 12's watermark records; decoding, the capability
   manifest, presence, fencing and the rules are C2b's. This is why the `boot-and-order` trace (tick 1, empty
   closure) and the `watermarks` trace up to the join already pass.
8. **BAKE with pristine chunks** returns `ERR_ORDER` ("needs worldgen") until C2b; without pristine chunks it
   works and starts the baked save's own lineage (the trace's case).
9. **Per-phase digests** (§4.8 item 5) are the full state hash after each phase, switched on by
   `SimContext::set_phase_digests` (native tools and tests), not by `PROFILE`: 16 hashes per tick would distort a
   profile.
10. **D6.** In simcheck builds, each phase ends with a NaN scan of the pools' float columns and the players'
    floats; a NaN panics with the phase's number (a trap). The encoders refuse NaN everywhere else.
11. **RNG golden vectors** (§4.3 says the schema package's fixtures hold them; they did not exist): C2 wrote them,
    in `game/test/rng/`: an independent Python implementation (`vectors.py`) and its output (`vectors.txt`), which
    `rng.rs`'s test reads. They cover every primitive, and 16 outputs of streams 1 and 2 for seeds 0, 1 and
    0xDEADBEEF.
12. **Chunk storage.** The modified chunks are boxed in a sorted `Vec` and `GENERATED` is a sorted `Vec`, so a
    record's position (rule 38's slice key) is a binary search away; a derived per-shard index of generated
    chunks lets the slicer find a shard's chunks directly.
13. **Tests in one binary.** Each integration test binary links the crate again (fat LTO under `ntest`), so
    `tests/core/` holds all of them. The allocation test's counting allocator is test code with `unsafe`
    (`#![forbid(unsafe_code)]` binds the crates' library code, which stays free of it).
14. **`simtool`** reads raw containers only (the golden saves are raw; deflate comes when bug bundles need it). A
    container's `prototypesHash` must match `--protos`, unless it is all zero (fixtures).
15. **`sim_supply_chunk`** checks its `chunk_data` record strictly and otherwise ignores it in C2a (rule 45); C2b's
    commits will take the answers they asked for.

No schema change, and no golden value is disputed.

### Open issues and follow-ups

1. **The `ntest` profile costs about 35 s per sim edit** (fat LTO, one codegen unit; the core test binary alone
   links for 28 s). I propose `lto = false`, `codegen-units = 16` and `incremental = true` for `ntest` in
   `game/Cargo.toml`, which is outside C2's paths. It would rebuild in about 1 s and keep optimised code.
2. **C2b's hooks are in place:**
   - phase 1's pipeline goes where `consume_seq` is;
   - phases 3 and 15;
   - `build` must make pristine chunks modified;
   - BAKE needs worldgen's regeneration;
   - `sim_supply_chunk` must store the answers to its own requests;
   - the `TestSequencer` belongs in `testkit`.
3. **Slicer costs that grow later:**
   - `TIMERS` is scanned linearly each tick (M0 has no timers). It needs a per-shard index once M1's ghosts create
     many.
   - `GLOBALS` is encoded every tick (542 bytes in M0).
   - Inserting into `GENERATED` is a memmove. That is fine for §10.6's 30,000 chunks, but endless maps need an
     order-statistics structure.
4. **Spec text to update:**
   - §4.3 should say that the RNG vectors live in `game/test/rng/`.
   - §4.6 should say that work timers are an ordered set and that the wheel holds wake timers.
   - §15.8 should state how load refusals split between `ERR_LOAD_FORMAT` and `ERR_LOAD_SCHEMA` (decision 3).
5. **`simtool`** reads raw containers only. Bug bundles from the browser will need deflate (M1).

### Review response (C2a-r1)

Codex review `pm/reviews/C2a-r1.md`: 5 major, 5 minor. All ten are **fixed**, each with a test that fails on the
reviewed code (commit 6051307). I checked that in a scratch worktree of that commit, which ran the same inputs.
The malformed loads run natively and in wasm32: the native test `review_c2a` writes them to
`game/test/sim-wasm/cases/`, and `test/sim-wasm/sim-wasm.test.ts` loads them into `sim.wasm`.

| # | Finding | Response |
|---|---|---|
| 1 | Remapping computed block offsets in `usize`, so native code and wasm32 could reach different slots | **Fixed.** `validate::check_references` runs before any remap: pool rows and entities must name each other by whole handle, and every `InvRef` must name an existing block. `remap::clear_block` computes offsets in `u64`, bounds-checks them and refuses with `ERR_LOAD_FORMAT`. Test case `remap-removes-a-chest-with-a-missing-block` (the reviewed code loads it with status ok); a valid removal still loads and zeroes the blocks |
| 2 | Malformed coordinates trapped or were accepted after overflow | **Fixed.** Footprints use `i64` and must lie inside the chunk-key range (±2²⁰ tiles), so no key aliases. Before any derived index is built, `check_entities` checks every live entity's prototype, pool, surface, generation, serial and footprint against the map bounds. `check_players` requires finite positions within the range, and `check_schedules` requires timers and worldgen requests to lie in the future. `create_entity` refuses anything outside the map. Cases: `chest-x2-i32-max` (the reviewed code panics), `chest-x2-aliases-a-chunk`, `chest-outside-the-map`, `player-position-infinite`, `worldgen-request-in-the-past` (the reviewed code accepts all four) |
| 3 | Enabling NO_SLEEP invalidated every watch-list id | **Fixed.** `set_no_sleep(true)` empties every list and the heap, frees all nodes and raises every sequence number, but keeps each list's id. Tests: `sched::no_sleep_keeps_the_watch_list_ids` (the reviewed code panics with an index out of range); the toy factory toggles NO_SLEEP every 1,000 ticks on its established lists and stays equal to the reference |
| 4 | Load accepted inventories too small for their owners | **Fixed.** `validate::check_inventories` checks: the canonical class for the owner's size (a chest's `inventory_slots`, the character's 80); empty slots past the size; known items at quality 0–4 holding at most a stack; limit bars and filters inside the size; hands empty, a ghost cursor, or a stack whose origin is a main slot. Cases: `swapped-inventories`, `items-past-the-inventory-size`, `stack-over-its-stack-size`, `limit-bar-past-the-size`, `hand-origin-past-the-size` (the reviewed code accepts all five) |
| 5 | The ABI blob store had no memory bound | **Fixed.** Limits are checked before copying: a blob is at most 8 MiB, 11 §3.2's limit (`ERR_INPUT`); at most 64 blobs and 32 MiB are held per tick (`ERR_LIMIT`). Lookup is a binary search over hashes, and a blob already held is not copied again. `sim_input` uses `try_reserve` and returns 0 instead of trapping. Test `the_blob_store_is_bounded`, natively and in wasm32 (the reviewed code accepts a 65th blob) |
| 6 | `serial_of` ignored the handle generation | **Fixed.** A stale handle has no serial (none), and the invariants compare whole handles. Test `a_stale_handle_has_no_serial` (the reviewed code returns the serial of the entity that reused the row) |
| 7 | A checked piecewise table could produce NaN | **Fixed.** Every breakpoint returns its stored value bit for bit, −0 included. A table whose `Δx` or `Δy` overflows is refused (`PiecewiseError::Overflow`), so interpolation stays between finite neighbours. Test `extreme_values_and_signed_zero` (the reviewed code accepts the MAX/−MAX table and turns an interior −0 into +0) |
| 8 | Wrapped long deadlines blocked unrelated timers | **Fixed.** A deadline past `u32::MAX` registers nothing: it can never come, since `World::tick` refuses to pass that tick. The heap fires every entry due at or before the tick. Test `a_deadline_past_the_last_tick_is_never_due_and_blocks_nothing` (the reviewed code never wakes the second sleeper) |
| 9 | Reclamation relaxed the bound and allocated | **Fixed.** The bound is now §4.6's own: after every call, nodes in use ≤ 2 × live registrations. A sweep visits only the lists marked dirty and filters the heap in place (`retain`); capacities are kept and the bound is restored after lists and timers fire. Tests: `stale_heap_timers_are_reclaimed_at_once` (the reviewed code keeps 50 stale nodes with no live registration); the toy factory checks the strict bound every tick; `sleeping_and_waking_allocate_nothing_once_warm` (20,000 ticks of sleeps, wakes, compactions and sweeps under the counting allocator; the reviewed code allocates) |
| 10 | Digest slicing scanned whole collections | **Fixed.** `TIMERS`, `STATS` and `WORLDGEN_PENDING` have per-shard indexes (`index::ShardBuckets`). Timers and requests live in an order-statistics block list (`index::BlockList`, rank O(n/256)); statistics are a sorted `Vec`. `Slicer::last_visited` counts the keyed records a slice reads. Test `populated_collections_slice_like_the_reference`: after 6,000 random edits, every shard equals the reference and reads only its own records (the reviewed slicer read all of them). Scale probe with 100,000 timers, 4,000 statistics keys and 5,000 requests: 0.064 ms mean per slice, 0.14 ms at most |

**The dev-loop decision (approved by the manager):** `game/Cargo.toml`'s `ntest` profile is now `lto = false`,
`codegen-units = 16`, `incremental = true`. A sim edit now rebuilds the `ntest` tests in 1–6 s (it was about 35 s),
and the whole `ntest` run takes about 3 s. Release keeps fat LTO.

**`simabi` now implements §15.8's table** over `SimContext`, through the generated `export_sim_abi!`:
- the input buffer;
- 8-byte-aligned envelopes;
- `sim_last_error`'s own buffer;
- the memory epoch;
- the panic hook calling `host_panic`.

Extraction, subscriptions, queries, `sim_pool_dir` and `sim_allocs` answer `ERR_ORDER` until C2c.

The table is exported only with the cargo feature **`full-abi`**. Without it, the module stays the M0 scaffold
(`sim_abi_version` = 0, no imports), because:
- `src/simworker/scaffold.ts` instantiates with `{ env: {} }`;
- `e2e/smoke.spec.ts` expects "ABI 0";
- both belong to the Shell package and fall outside C2's paths.

`test/sim-wasm/` builds with the feature. **When C3's loader lands, `full-abi` becomes the default, and the smoke
test expects ABI 2** (a one-line change in `crates/simabi/Cargo.toml`, plus C3's smoke test). The full module
passes the release feature gate (451 kB after `wasm-opt -O3`).
