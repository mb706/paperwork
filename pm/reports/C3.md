## Summary

### The sim worker (`game/src/simworker/`, 3,070 lines; `fake*` untouched)
`shell.ts` (`SimShell`) wraps one `sim.wasm` instance per worker and holds one world (decision 10). Everything that
decides state happens in the module, and the shell keeps no competing state (§3.6). The modules:
- **`module.ts`** instantiates the `WebAssembly.Module` that the main thread posts. Its handshake checks, in order:
  - `ABI_VERSION` (2);
  - the memory export;
  - `sim_schema_hash` against `SCHEMA_HASH`, naming both hashes on a mismatch;
  - every export that `checkExports` names.

  The M0 scaffold is refused as "ABI 0". `SimInstance` holds the hot exports (input, tick, digest, pending chunks,
  extract, flags) and handles statuses and envelopes, `sim_last_error` and traps. A trap is a `TrapError` with the
  panic hook's message, and a trapped instance is never called again.
- **`lease.ts`, the `MemoryLease`** (boundary rule 4). After every call it reacquires its views if memory grew or
  `sim_memory_epoch` moved. In dev builds, stale views throw (`StaleViewError`).
- **`sequencer.ts`, the `LocalSequencer`:**
  - stamps each action for the next tick, refuses seqs that do not rise, and drops system types sent by players;
  - writes input generations (D22) and gives system actions their own seqs;
  - applies the admission function (`src/shared/admission.ts`, below) and frames batches;
  - carries blobs.

  `ReplaySource` (closure logs) and `PortSource` (the multiplayer closure port, 11 §2.4) implement the same
  `ClosureSource`. Closures are written straight into the module's input buffer.
- **Pacing (`clock.ts`, `waker.ts`):**
  - Clock generations `{gen, fromTick, speed, paused}`. Pause, resume, a speed change and a rebase each start one,
    and each is reported as a `clock` message.
  - A wake runs at most 3 ticks. A backlog over 6 ticks rebases.
  - Timers fire 2 ms early. A wait under 4 ms is a self-posted `MessageChannel` message instead of a timer.
  - Catch-up runs in 12 ms slices with extraction off and the `HISTORICAL` flag set. It covers replays and a
    closure port more than 30 ticks behind.
  - Test mode runs `seq step n`.
- **Packets (`packets.ts`):**
  - The pool holds three 256 KiB transferable buffers.
  - The shell writes `state_gen` (offset 8) and `view_seq` (offset 16) into each packet header.
  - With no free buffer, extraction waits for an `ack` (backpressure). A bigger packet grows a buffer by doubling.
  - A buffer that comes back unchanged keeps its views.
  - A world's first packet is FULL and unsolicited, right after `bound` (§3.4 step 2).
- **Subscriptions and queries (`queries.ts`):**
  - `sub` and `unsub` are kept per generation.
  - Four queries run at a time, within a 2 ms budget per wake, and the rest wait.
  - `cancel` drops a query, and queries of another generation are dropped.
- **Closure logs, the digest ring and replay (`closurelog.ts`, `digests.ts`):**
  - The shell records every closure and blob since the log's base: the last save, or the world's start (§8.5).
  - The digest ring holds 36,000 ticks of d_t.
  - `replay` runs a log in a fresh world and reports the first digest that differs.
- **Saves and checkpoints (`saves.ts`, `remap.ts`):**
  - `save` copies the sections out of linear memory and sends them to the IO worker over its port.
  - Autosaves rotate through 3 slots.
  - `snapshot_marker` makes a checkpoint copy with its manifest (§8.6).
  - Loads remap by name from the save's name tables (§8.3).
- **Worldgen (`worldgen.ts`):**
  - Requests from `sim_pending_chunks` go to the gen pool, both at world creation and after every tick.
  - Answers are supplied between ticks, before their commit tick.
  - A late or missing answer falls back to inline generation (D12).
- **Traps.** A panic or a runtime error stops the shell. It posts `trap` with the message and a bundle: the log's
  base, the closure log up to the trapping tick, and the digest ring.

### The main thread's side (`game/src/app/`, 1,100 lines)
**`sim-host.ts`, `SimHost`.** It is the only allocator of state generations, and the renderer, UI and audio see the
simulation only through it.
- **World replacement (S15).** A new game, a load, a trap recovery and a replay each get a fresh worker (decision
  10). SimHost accepts the current generation's messages only, plus the new generation's `ready`, `bound` and first
  packet. When that packet arrives, the generation switches: SimHost re-sends the view and every subscription and
  rejects older queries (`events.generation` tells the consumers).
- **Retiring the old worker.** Single player terminates it at once (§3.1). `background: true` keeps it playing
  until the new FULL packet: this is the multiplayer re-sync swap (S11).
- **Seqs:** nextSeq = max(loaded, accepted, pending) + 1. A replacement discards pending actions.
- **Saves.** Autosave runs every 5 minutes into 3 slots. `navigator.storage.persist()` is requested at the first
  save.
- **The hidden page** pauses single player in a new clock generation, and autosaves if the last save is older than
  a minute (07 §19.3).
- **Trap recovery (§3.6):**
  1. the trap notice (`events.trap`);
  2. the bundle, assembled with its base save and stored in OPFS under `reports/<time>/` (`save.save`,
     `closures.pwlog`, `digests.bin`, `report.json`);
  3. the base save, reloaded into a fresh worker.

  `exportBugBundle()` and `replay()` are available too.

**The other files:**
- `io-client.ts`;
- `inline.ts`, which runs a worker's code in-process behind a `MessagePort` (for `?sim=inline` and the Node tests);
- `wasm.ts`, which uses `compileStreaming` with an `arrayBuffer` fallback;
- the worker entries `workers/sim.ts`, `gen.ts` and `io.ts`.

**The M0 page (`main.ts`)** compiles `sim.wasm` and `gen.wasm` once (§9.7) and boots SimHost. It shows
"sim.wasm ABI 0, refused: …" until C2's module lands, then "sim.wasm ABI 2, world bound at tick 0". It autosaves,
saves on `pagehide`, pauses when hidden and shows the trap notice. The UI package replaces this page.

### The worldgen and IO workers (`game/src/genworker/`, `game/src/ioworker/`, 700 lines)
- **The gen worker** runs one `gen.wasm` instance per worker. Its handshake checks `GEN_ABI_VERSION` 1 and the
  schema hash. It answers chunk requests from the sim workers' ports, and map previews on its own channel. If its
  module is refused, all generation is inline.
- **`IoService`:**
  - compresses: each section with fflate deflate level 6, kept raw when that is not smaller (§8.1);
  - hashes with WebCrypto SHA-256 and writes and verifies the save container;
  - refuses a save over quota;
  - lists, deletes, exports and imports saves;
  - stores checkpoints with their manifest, in 64 KiB chunks, and the files of bug bundles.
- **Storage (§8.2):** OPFS with sync access handles; otherwise IndexedDB (`idb`), database `game` v1 with its six
  stores.

### `window.__game` (`game/src/dev/game-hooks.ts`)
- **The hooks:** `step`, `dispatch`, `query`, `hash`, `digest`, `allocs`, `memory`, `save`, `load`, `inspect`,
  `speed`, `pause`, `resume`, `replay`, `exportBugBundle`, `flags`, `panic` and `tick`.
- **`register`** adds the renderer's and UI's hooks: `ui.*`, `render.*`, `camera` and `loadScenario`.
- **Loading:** dev builds and `?dev=1` load them through a dynamic import (§9.7).
- **The browser bench** `src/dev/shell.html` is what e2e drives.

## Decisions and deviations
1. **Files outside the brief's write list.** Each change is additive.
   - **`src/shared/protocol.ts`** (C1c's file). The messages added are marked "(C3)" and are optional for the fake:
     - main → sim: `hidden`, `replay`, `save.name`;
     - sim → main: `refused`, `saveFailed`, `error`, `bundle`, `replayed`, `trap.bundle`;
     - DevOps: `allocs`, `memory`, `bundle`, `panic`, `system`;
     - optional `BuildManifest` and `SaveMeta` fields.
   - **New: `src/shared/admission.ts`, `io-protocol.ts` and `gen-protocol.ts`.** The worker protocols that §3.2
     leaves open, and the admission function shared with C2.
   - **`src/app/main.ts`** was rewritten, and `sim-host.ts`, `io-client.ts`, `inline.ts` and `wasm.ts` were added.
     S15 makes the main thread allocate generations, so the shell needs its main-thread half.
   - **`tsconfig.app.json`** gained references to the worker projects (TS6307).
   - **`e2e/smoke.spec.ts` and `e2e/release.spec.ts`** use the status pattern in `e2e/status.ts`, which accepts both
     "ABI 0, refused" and "ABI 2, world bound". They pass both before and after C2's module lands.
   - **`test/fixtures/admission/cases.txt`** is shared with C2's `TestSequencer`.

   Nothing in the crates, the schema, the generated code, `design/**` or the golden set changed.
2. **Versioning, and the quality bar's "every message versioned".** One handshake per worker versions the whole
   conversation; there is no version field on each message:
   - `boot` carries the build manifest's `protocolVersion` and `schemaHash`, and the schema hash covers
     `PROTOCOL_VERSION` and `ABI_VERSION`;
   - the worker answers `ready {abi, schemaHash, buildHash}` or `refused`;
   - binary payloads carry their own versions.

   Main thread and workers come from one content-addressed build (§9.7), so a mismatch means a stale cache.
3. **Generation tags.** As §3.2 says, every message that refers to a world carries `gen`, and packets carry
   `state_gen` in their header. Worker-scoped controls (`seq`, `ack`, `save`, `dev`, `hidden`) carry none, as in
   C1c's list. A worker holds one world, and SimHost routes every message by the session of the worker that sent
   it, so a retired worker's messages are dropped anyway.
4. **Admission (§15.3).**
   - A new batch starts when the player changes or the seq is not the previous seq + 1, since a batch header holds a
     first seq and a count.
   - The closure cost counts headers and payloads against CLOSURE_MAX − SYSTEM_RESERVE.
   - The wire cost also counts blobs.

   The fixture is the contract with C2.
5. **What trap recovery reloads (§3.6, 10 §12 exit).** §3.6 says "the last autosave". The shell reloads the save
   that the closure log is based on, which is the last save of any kind, or the world's start held in memory if
   nothing was saved yet. The bundle's log starts at that save, so the reload and the bundle stay consistent.
6. **The dev panic is `debug_dump(0xFFFFFFFF)`**, a system action sent by `__game.panic()` (`DEV_PANIC_DUMP_ID`).
   This is a **proposal to C2**: panic on it in dev and `simcheck` builds. The stubs implement it.
7. **`navigator.storage.persist()` runs on the main thread**, at the first save (§8.2), because `persist()` is
   exposed to windows only. The IO worker reports the estimate.
8. **The stubs live in `game/test/stubs/`**, not `crates/`, which C2 owns. They depend on the generated schema
   crate by path, so ABI drift breaks their build.
9. **The golden digests run before the real module exists.** The brief asked for them with the real module. C1c's
   reference model runs behind the ABI (`model-module.ts`), so the digests, packets and traces already go through
   the shell.
10. **A fix to `Clock.due()`:** it adds 1e-6 ticks. A wake at exactly a deadline computed by `nextAt` sometimes did
    not see its tick as due, because of rounding. That was one wake in three in the probe.

  - Every sim ABI trace matches its statuses, envelope payloads, `sim_last_error` and state assertions.

  - The remap-load trace's load report and state hash match.
- **Allocation (A1 open issue 7).** `steady-probe.ts` runs in a child `node --expose-gc`. After the warm-up, three
  windows of 20,000 ticks each allocate a constant 11.2 KB, whatever the window's length:
  - 0.56 B/tick over 20,000 ticks, 0.19 over 60,000 and 2.2 over 5,000;
  - the same with a packet per tick (clock-driven) and in `seq step`.

  That constant is the measurement itself, so **0 bytes per tick**, and nothing is retained. V8's sampling heap
  profiler finds no site in the shell over 20,000 frames. On the way, profiling found five allocation sites, now
  fixed:
  - `Array.shift`;
  - `Map.clear()` on an empty map;
  - boxed digest words;
  - timer doubles;
  - **a real bug:** after each tick, the pending-chunk count was read from the envelope's length word. Requests in
    the middle of the game now reach the pool, and a test covers them.
- **The boundary audit (§3.6 rule 3).** Per tick the shell calls exactly `sim_input`, `sim_tick`, `sim_digest` and
  `sim_pending_chunks`, plus `sim_input` and `sim_extract` per extraction, whatever the world holds.
- **Clean checks:** `tsc -b`, Biome, check-arch (0 violations, 280 files), and cargo fmt and clippy on the stubs.

### The findings
| # | Fix | Test (`review-r1.test.ts`) |
|---|---|---|
| 1 | **Saves.** Every write makes a new version file (or record), checks that every byte was written, the size and the flush, then publishes it in one IndexedDB transaction. The previous version goes only after that commit. Orphans are swept when the tab becomes the owner (`storage.ts`). | OPFS with a quota error, a short write and a commit under a stale owner; IndexedDB under a stale owner. |
| 10 | **One tab at a time** (`ownership.ts`): a Web Lock and an owner epoch that every commit checks. *Take over* runs over a BroadcastChannel: the owner saves (an exit save) and drops to read-only (pause reason `storage`). An owner that does not answer has its lock stolen. A tab never takes the saves back by itself. | Two in-process tabs share a lock; e2e: two pages in Chrome and Firefox. |
| 9 | **The bundle's base.** The closure log's base is the last autosave (or exit save), named by version: file and SHA-256. It is pinned while it is a base, so overwriting the save keeps it. Manual saves and checkpoints no longer rebase the log. The recovery reads that exact version. | The base slot is overwritten before the trap; a manual save after the autosave. |
| 2 | **Stale recovery.** A replacement token is checked after every await of the trap handling, before the notice and before the replacement. | A new game started while the bundle is being kept. |
| 3 | **Lifecycle.** Every phase is a deferred that rejects on failure, supersession, exit or close. A failed session's worker is terminated, and its queries, saves, steps and dev requests reject. | A trap in the first extraction; a replacement superseded before `ready`; `close` with requests waiting. |
| 4 | **Wake storm.** Extraction demand is kept apart from runnable work. A wake comes only when an extraction can run: on `hidden: false`, at the end of catch-up, and on `ack`. | A hidden, paused world with a view; no free buffer. |
| 5 | **Blob timing.** Blobs are verified synchronously at intake (`src/shared/sha256.ts`, tested against `node:crypto`), so actions are stamped as they arrive. | A `release_inputs` right after an act whose walk names a blob; a bad blob. |
| 6 | **The worker swap.** `replace(world, {background, closurePort, handover})` boots the shadow with the room's port. The shadow holds its first packet until it has caught up to the handover tick, and the old world plays on until then. | A re-sync from tick 10 to tick 40. |
| 7 | **Port blobs.** A message is refused before the horizon moves if a blob does not hash to its name or a named blob did not come. Blobs are counted by the buffered ticks that name them and dropped after the last. | `PortSource` directly. |
| 8 | **Remapped bases.** A remapped load's base is a snapshot with this build's prototypes hash and name tables, and the world's settings. | The remap-load input, reloaded from its base. |
| 11 | **Queries.** Cancelling a running query fills its slot. `busy` counts waiting queries too. | Five queries; the four running are cancelled. |
| 12 | **Steps.** `seq {step, id}` is answered by `stepped {gen, id, tick}`, and SimHost serializes steps. For a worker without `stepped` (`ready.steps` absent: the fake), SimHost waits for a packet at the target tick. | `step(1)` and `step(2)` sent at once. |
| 13 | **Pausing.** Pause reasons `user`, `hidden`, `menu` and `storage`: the world runs only when none holds. | Pause, hide, show. |

### Decisions and deviations
1. **The recovery base is the last autosave.** §8.5 ("since the last autosave") and 10 §12's M0 exit ("reloads
   the last autosave"). An exit save counts, since it takes an autosave slot. This replaces decision 5 of this
   report.
2. **The saves' owner** lives in the `settings` store of database `game` v1, under key `saves.owner` (no schema
   change). The tabs talk on the lock and channel named `paperwork:saves`. A tab that is not the owner may run a
   world but cannot save, and the UI offers *Take over* (C5's dialog).
3. **Version files** are named `<name>~<sha256 prefix>~<time and counter>.save`. A record of the first layout
   (`<name>.save`) still reads.
4. **Protocol additions (C3-r1), for C4's and C5's merges.**
   - Main → sim: `seq.id`, `world.handover`.
   - Sim → main: `ready.steps`, `stepped`.
   - Saves: `SaveMeta.version`; `LogBase {kind: 'save', version}`.
   - IO: `pin`, `unpin`, `unpinAll` and `bundle` requests; `read` and `export` by version; `failed.notOwner`; on the
     IO worker's channel, `owner`, `takeover` and `release`.
   - SimHost: the `trap` event carries `report` (not the bundle), and there is a new `storage` event. Its API
     adds `on`, `step`, `exit`, `listSaves`, `storage`, `pauseFor`, `setMenuPause`, `takeOver`, and `replace`'s
     options.

   `tsconfig.app.json` keeps its references to the worker projects, which `src/app` imports.
5. **`app.ts` starts no world.** `placeholder(app)` shows the M0 page until C5's `mountUi(app)` replaces it.
   - C5's `Session` currently does SimHost's job a second time (workers, generations, saves). Its merge should
     build the UI's `SessionApi` over `app.host`.
   - C4 attaches through `app.host.on('packet' | 'generation')`.
6. **The e2e bench page** waits until the dev server has settled. On a fresh server, the data stage and
   schema-gen reload connected pages for a few seconds.
