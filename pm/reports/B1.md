## Decisions and deviations

Each is also reflected in 10's "Changes in v2" table or in the section named.

1. **Worldgen moves to Rust too** (10 §3.1, §5.18; not named in the brief). The sim queries the town layer synchronously (staffing, U4), and worldgen's output becomes world state, so IMPL-1's "all authoritative state and rules in Rust" covers it. The crate is linked into the sim and also built as `gen.wasm`; each pool belongs to one sim worker, and answers carry the world's hash.
2. **Inline chunk commits** replace "the sim waits for the worker" (10 §5.18): a late chunk is generated by the sim itself at its commit tick with the same pure function. No blocking wait across threads; native tests, replays and catch-up need no pool (D12, R28).
3. **The set of generated chunks is saved** (`GENERATED`), and **pristine chunks regenerate lazily** as a pure cache (10 §4.4). Round 5 regenerated them "on load", which would take far longer than the 3-s load budget at 30k explored chunks, and it never saved which chunks existed, which changes heat flow and agent behaviour after a load.
4. **Expressions compile to bytecode, interpreted in Rust** (10 §15.2), not to generated Rust: data edits need no Rust rebuild (release builds take about 67 s), `prototypes.bin` stays self-contained under `prototypes.hash`, and the formulas run a few times a minute. `prototypes.bin` has a binary header, so Rust needs no JSON.
5. **Derived pools are ordered by canonical keys, never pool index** (D3 f, new): they are rebuilt on load with different indices.
6. **Belt update order** (10 §5.3): a downstream-first rank by Kahn's algorithm on the reversed feed graph with a min-heap keyed by line identity `(entity serial, belt index, lane)`; cycles are broken at the lowest-identity unranked line, which may open a one-tick gap there (10 §14 #16, R21). A1's kernel got the order from its generator's numbering.
7. **One fresh worker per world** (10 §3.1): new game, load, trap recovery and re-sync all swap in a new worker through S15. Linear memory never shrinks. In single player the old worker goes first, so two late worlds never share the tab's memory.
8. **A canonical allocator** (10 §4.5): lowest free slot, saved high-water marks, handle generations surviving frees, and a slot heap of per-size-class arenas whose free state is a function of the live inventories.
9. **Full-state hash XXH64** over canonical section bytes (was xxHash32 over pools plus JSON); digests are XXH64 too, in-crate.
10. **Binary records instead of canonical JSON** for cold data and globals, with stable field ids (protobuf-like loading by field id).
11. **The render packet** (10 §15.4): one binary buffer per frame, written whole by `sim_extract`, adopting A1's suggestion of **per-line gap arrays expanded on the main thread**. The sim supplies line geometry with a globally unique geometry generation; both sides compute the same "held set" of chunks, so caches stay coherent without acknowledgements.
12. **UI data only through projections and subscriptions**, generic change detection by record hash, `GONE` status for vanished targets, a 60-tick cadence that survives skipped extractions.
13. **Seqs are assigned by the main thread** (continuing from `bound.lastSeq`), so it can name its own unconfirmed creations by creation id; **the sequencer writes input generations** into held-input actions at stamping time, so the main thread never needs to know them. D21 is a framing check against the saved `last_seq` in every build, not a debug assertion.
14. **Action type ids are our own, stable and append-only**; names mirror Factorio's `input_action`, whose numeric values are not a stable published contract.
15. **Payload limit 65,531 bytes** (A2 had 65,535): wire entries carry a whole encoded action in a `u16` length. Wire entries also list the blobs an action names, so the relay never parses payloads.
16. **Digest epochs are not world state**: the relay assigns them and the net worker reports them; checkpoints carry only `r` (A2's text had both, inconsistently).
17. **Previously unsaved state now saved**: last tick's electric satisfaction per network and class (phase 2's timers read it), timer owners (total fire order), chunks' rule versions (read by the Area scanner, which round 5 tied to view counters), per-player inventory versions (digest input), the world's tick, seed and settings in `GLOBALS`. The thermal bucket is now a function of chunk coordinates, not a chunk ordinal.
18. **Banned float methods** (verified to fire): besides A1's list, `f64::max`, `min`, `clamp` and `powi`, the f32 variants, `libm::fma`, `Instant::now`, `SystemTime::now`, `thread::spawn`.
19. **Offline characters' crafting queues pause** with their reservations (10 §5.1, §14 #17).
20. **The settings audit** (D11) is a table in 10 §7.6, with two new actions, `set_player_setting` and `set_game_setting`, and rule scenario R29.
21. **The audio-thread budget is left to WP B2** (10 §11 points to §9.4): B2's brief, written after mine, gives it to B2.
22. **10's numbering is stable**: new subsections were appended (§3.6, §3.7, §4.8, §8.6, §9.7 stub), and the contracts became **§15** rather than an appendix, so that "10 §15.x" references are checked by `r3_xref.py`. D-rule and S-seam numbers are A2's; D5 is marked retired.
23. **Small edits outside the brief's list**, for consistency with binding decisions: §6.2 and §6.7 name the style composites as constants (IMPL-5), §7.4 points the UI palette to *Survey* (IMPL-5), M1c's music line follows A4 (IMPL-6). §9 itself is untouched except the stub heading B2 may fill.
24. **`design/multiplayer/DESIGN.md` is left in place** (outside my write scope); 11's header says 11 supersedes it.
25. **Sizes** (10 §12): M0 is about three times round 5's estimate (28k / 10k lines, 24–32 agent-days, about 14–18 calendar days in parallel); M1–M4 +10%; MP 12k / 8k lines, 14–18 days. M0–M4 total 138–179 agent-days (was 110–141).

## Review by a second agent: findings and fixes

**Critical.**
- C1 *The set of generated chunks is never saved.* **Fixed:** the hashed `GENERATED` section; pristine chunks regenerate lazily; R28 extended (10 §4.4, §8.1).

**Major, determinism.**
- M1 *Phase-2 timers read last tick's satisfaction, which nothing saved.* **Fixed:** saved per network and class in `NETWORKS`; D8 lists it.
- M2 *Tick, seed, settings and surfaces were in no hashed section.* **Fixed:** in `GLOBALS`; the header keeps copies.
- M3 *Timer order not total; owner ids lost on save.* **Fixed:** `(dueTick, serial, eventCode, owner)` at runtime, in the fire order and in the save.
- M4 *Slot-heap allocator unspecified; free-slot reset wiped handle generations; `rows` undefined.* **Fixed:** per-size-class arenas with lowest-free-block allocation, saved high-water marks, generations survive frees.
- M5 *Line rank and identity underdetermined; splitter inputs collide.* **Fixed:** Kahn's algorithm with a min-heap and cycle breaking; identity `(entity serial, belt index, lane)`.
- M6 *"Inventory version" undefined.* **Fixed:** a saved per-player counter.
- M7 *The Area scanner read unsaved view counters.* **Fixed:** a saved per-chunk rule version.

**Major, M0 contracts.**
- M8 *D21 and debug checks depended on an undefined "dev build".* **Fixed:** D21 is a framing rule in every build; "dev build" means the `simcheck` cargo feature.
- M9 *The main thread could not form creation ids.* **Fixed:** the main thread assigns seqs, from `bound.lastSeq`.
- M10 *No transport for closures or blobs.* **Fixed:** `closurePort`, the `closures` message, `act.blobs`, `submit(…, blobs)`.
- M11 *Packet assembly handoff undefined.* **Fixed:** `sim_extract` writes the whole packet; the shell fills `state_gen` and `view_seq`; offsets from the packet start; `FULL` defined.
- M12 *Mirror and cache coherence underspecified.* **Fixed:** the held set (visible rectangle plus one chunk, one generated function, applied at extraction and on receipt), geometry dropped with its chunks, a global `geom_gen`, `CHART` on entry.
- M13 *The fake sim needed encoders nothing generated.* **Fixed:** TypeScript writers for every record.
- M14 *The crate graph could not host the worldgen contract.* **Fixed:** a generated `schema` crate; the `gen_init` layout.
- M15 *Rust would have parsed JSON in `prototypes.bin`.* **Fixed:** a binary header.
- M16 *Sprite manifest ambiguous.* **Fixed:** ordered arrays, a frame table per resolution, parts as `{first, count}`, the example corrected.
- M17 *Worldgen answers carried no world identity.* **Fixed:** a world hash from `gen_init`, echoed in `ChunkData`, checked by `sim_supply_chunk`; pools per sim worker.

**Major, multiplayer.**
- M18 *The digest epoch meant three things.* **Fixed:** relay-owned only; checkpoints carry `r`; the joiner adopts the epoch from `WELCOME`/`RESYNC`.
- M19 *Seq watermarks never seeded.* **Fixed:** seeded from the save's `sim_meta`; re-derived from the log after a restart; roster slots claimed by name.
- M20 *The relay needed to parse payloads to find blobs.* **Fixed:** entries list their blobs.
- M21 *Regenerating pristine chunks broke the load budget.* **Fixed** with C1 (lazy regeneration; §11's note).

**Minor** (all fixed): widths unified or stated (`schema_version` u16, tile ids u8, surfaces, `CHART` version u32, 32-byte build hashes in dev builds); the `clock` message's `clockGen`; `sim_memory_epoch` exempt from invalidation; the manifest kept outside the container; one self-contained closure-log format; action tails (`bytes`, `list`, `blob_or_bytes`); the remaining layouts (query ids, the subscription tail flag and `sub_id` 0, `COLD` and column offsets, nested lists, the load report, `ProtoKind`, `alt_icon`, the seed and xoshiro seeding); `CHUNK_TILES` 1,036 bytes and the sort order; saved homes for map tags, ground items and per-network statistics, and the thermal bucket by coordinates; the start area generated inline; town recursion as an explicit stack; single-player replacement order and the generation switch; blueprint library by name and the scripted opening as an input script; tests for D10, D11 (R29), D16 and D17, `host_now`'s wording, heavy mode in M0's exit, proptest shrinking; input generations stamped by the sequencer; the vehicle driving-mode setting; 11's numbers, message widths, chunk sizes, chunked blobs, the room-cost wording and the player cap; the TypeScript residue (`Uint32`, `Float32`, `uint32`); "four" spikes; Changes row 27; the Artifact CSP risk (§13).
