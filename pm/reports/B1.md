## Decisions and deviations

Each is also a row of 10's "Changes in v2" table.

1. **Worldgen moves to Rust too** (10 §3.1, §5.18; not named in the brief). The sim queries the town layer synchronously (staffing, U4), and worldgen's output becomes world state, so IMPL-1's "all authoritative state and rules in Rust" covers it. The crate is linked into the sim and also built as `gen.wasm` for the worker pool.
2. **Inline chunk commits** replace "the sim waits for the worker" (10 §5.18). A late or missing chunk is generated by the sim itself at its commit tick with the same pure function, so there is no blocking wait across threads, and native tests, replays and catch-up need no pool. D12 and R28 test it.
3. **Expressions compile to bytecode, interpreted in Rust** (10 §15.2), not to generated Rust: data edits need no Rust rebuild (release builds take about 67 s), `prototypes.bin` stays self-contained under `prototypes.hash`, and the formulas run a few times a minute. The data stage validates with a reference interpreter of the same bytecode.
4. **Two prototype outputs**: `prototypes.bin` (schema-generated tables; the sim needs no JSON library) and `prototypes.json` (UI and renderer).
5. **Derived pools are ordered by canonical keys, never pool index** (D3 f, new). A1's bitsets fix NO_SLEEP equivalence for saved pools, but derived pools (lines, segments, networks) are rebuilt on load with different indices, so any order by index would break join equivalence.
6. **Belt update order** (10 §5.3). A1's kernel got downstream-first order from its generator's numbering; the spec now gives a rule for any build order: a topological rank with sinks first, ties by `(front belt serial, lane)`, recomputed lazily before phase 8, with the active bitset indexed by rank. A belt loop is cut at its lowest-identity line, which may open a one-tick gap at that one boundary (10 §14 #16, R21).
7. **One fresh worker per world** (10 §3.1): new game, load, trap recovery and re-sync all swap in a new worker through S15. Linear memory never shrinks, and the swap path then gets exercised constantly.
8. **Full-state hash XXH64** over canonical section bytes (was xxHash32 over pools plus JSON); per-tick digests and the rolling digest are XXH64 too, in-crate.
9. **Binary records instead of canonical JSON** for cold data and globals, with stable field ids (protobuf-like loading by field id). Rust would otherwise need a JSON library in the module.
10. **The render packet** (10 §15.4): one binary buffer per frame with a section table, adopting A1's suggestion of **per-line gap arrays expanded on the main thread** (4 bytes per item, against 16 and about 8 ns per sprite of worker time). The sim supplies line geometry with a geometry generation, so the main thread does no gameplay arithmetic. Daylight travels in the header, so the renderer never recomputes the day table.
11. **UI data only through projections and subscriptions**, generic change detection by record hash, `GONE` status for vanished targets.
12. **Action type ids are our own, stable and append-only**; names mirror Factorio's `input_action`. A1 proposed Factorio's numbering, but its numeric values are not a stable published contract.
13. **Payload limit 65,531 bytes** (A2 had 65,535): the wire's `ACT`/`TICKS` entries carry a whole encoded action (4-byte header plus payload) in a `u16` length.
14. **Seq continuity in single player**: the World saves each player's `last_seq` and a `last_system_seq`, which the `LocalSequencer` continues from, so D21's assertion holds across loads.
15. **Banned float methods** (verified to fire): besides A1's list, `f64::max`, `min`, `clamp` and `powi`, the f32 variants, `libm::fma`, `Instant::now`, `SystemTime::now`, `thread::spawn`. `det::fmax`/`fmin`/`powi` are defined as comparisons and a fixed multiplication order.
16. **Offline characters' crafting queues pause** with their reservations and resume on return (10 §5.1, §14 #17). A2 only said they "neither walk, mine nor craft".
17. **The settings audit** (D11) is a table in 10 §7.6: auto-sort and "pick ghost item" are per-player world state; trimmed collision is global world state; everything else is client-only. Two new actions: `set_player_setting`, `set_game_setting`.
18. **The audio-thread budget is left to WP B2** (10 §11 points to §9.4), because B2's brief, written after mine, gives it to B2. IMPL-6 said "the engine work package"; B2 is the one that owns §9.4.
19. **10's numbering is stable**: new subsections were appended (§3.6, §3.7, §4.8, §8.6, §9.7 stub) and the contracts became **§15** rather than an appendix, so that "10 §15.x" references are checked by `r3_xref.py`. D-rule and S-seam numbers are A2's; D5 is marked retired, not renumbered.
20. **Small edits outside the brief's list** for consistency with binding decisions: §6.2 and §6.7 name the style composites as constants (IMPL-5), §7.4 points the UI palette to *Survey* (IMPL-5), and M1c's music line follows A4 (IMPL-6). §9 itself is untouched except the stub heading B2 may fill.
21. **`design/multiplayer/DESIGN.md` is left in place** (outside my write scope); 11's header says 11 supersedes it.
22. **Sizes** (10 §12): M0 is about three times round 5's estimate (itemised: 28k / 10k lines, 24–32 agent-days, about 14–18 calendar days in parallel); M1–M4 +10% (Rust is about 1.2× the TypeScript lines in A1's kernels; boundary work per feature, A1-r1); MP 12k / 8k lines, 14–18 days. M0–M4 total 138–179 agent-days (was 110–141).
