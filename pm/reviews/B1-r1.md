1. **Critical — 10 §15.1–§15.2, §15.5, §15.8–§15.11: the contracts are not yet independently implementable.** Projection layouts are summaries; `new_world`, `sim_meta`, load reports, several ABI outputs and `prototypes.json` lack complete schemas. Numeric registries and namespace mappings are also deferred. Agents must invent interfaces. **Fix:** make the schema-first package’s acceptance gate explicit: committed M0 schemas, generated APIs, exact ABI signatures, prototype data, fake worker and independently reviewed binary fixtures must land before parallel coding.

2. **Critical — 10 §8.5: closure logs cannot be parsed unambiguously.** Sparse closure records have no count, byte length or terminator before the optional digests and mandatory blobs. The next `u32` could begin any of them. **Fix:** length-delimit each region or provide a directory; specify empty-log encoding and reject truncated or trailing data. Commit fixtures with and without digests and blobs.

3. **Major — 10 §15.1: schema hashing discards layout information.** Payloads use declaration order, but `SCHEMA_HASH` canonicalises mappings by sorting keys. Reordering fields can therefore change bytes without changing the schema hash. **Fix:** represent ordered fields as arrays and hash the resolved layouts, including offsets, padding, widths and enum values. Test that every wire-layout change changes the hash.

4. **Major — 10 §3.6, §15.4–§15.5, §15.8: extraction ownership is unresolved.** Extraction drains events, remembers sent geometry and hashes, advances subscription versions and updates held sets, despite taking `&World`. The shell also owns a subscription “table.” Two agents can build competing state machines. **Fix:** specify `SimContext { World, PresentationState }`, assign each mutable presentation field one owner, and define extraction as borrowing immutable World plus mutable presentation state. D9 needs continuation-equivalence tests with different read schedules.

5. **Major — 10 §15.8: ABI framing contradicts itself.** The general rule wraps outputs as `{len, bytes}`, while `sim_schema_hash` describes a raw 32-byte pointer and `sim_last_error` another header. `sim_extract` describes directory-and-sections, whereas §15.4 requires the complete packet. **Fix:** publish one normative signature/layout table, explicitly declaring exceptions, the exported memory, error reporting for pointer-returning calls and input/output lifetime rules.

6. **Major — 10 §4.3, §4.5, §8.1, §15.1: canonical saves have incompatible interpretations.** Handles supposedly never enter saves, yet generated saved pool fields include `EntityHandle`. Lists may declare `order: none`, without a canonical serialization order. Save alignment also lacks an explicit rule after the variable-length JSON header. **Fix:** define handle-to-serial conversion and two-pass loading, canonical sorting for unordered collections, column-directory ordering, and exact padding origins.

7. **Major — 10 §4.4, §8.3: pristine regeneration breaks migration semantics.** `GENERATED` preserves existence, but not the worldgen algorithm/data version needed to reproduce old pristine terrain. Loading after prototype or generator changes can silently change explored land and resources. **Fix:** retain versioned generation rules, materialise old pristine content during migration, or explicitly refuse unsupported migrations. Define lineage handling when migration changes state.

8. **Major — 10 §4.8; 11 §5.1, §7/S7: digest coverage is not specified.** Entity fields, modified chunks and cold records do not explicitly partition inventory contents, network contents, allocator metadata, timers and every remaining saved section. “Global sections” could instead cause a large once-per-minute scan. `d_t` encoding, closure checksum and initial `r` are unspecified. S7 still says checkpoints save the epoch. **Fix:** generate an exhaustive section-to-shard mapping and exact digest encodings; remove checkpoint epochs and pin new-world/load lineage vectors.

9. **Major — 10 §15.3: atomic validation conflicts with watermark updates.** Framing must finish before mutation, but validation advances saved `last_seq` batch by batch. A malformed later batch could partially consume sequences. Arithmetic such as `first_seq + count − 1` also lacks overflow handling. **Fix:** preflight using temporary watermarks, checked arithmetic, complete enum/tag/length validation and blob availability; commit bookkeeping only after the entire closure passes.

10. **Major — 10 §15.3; 11 §3.2–§3.4: closure limits do not survive network conversion.** The relay has no defined overflow admission policy matching the local sequencer’s spill rule. A bounded `TICKS` frame can expand when regrouped into 16-byte batch headers. One tick cannot straddle messages. **Fix:** bound the resulting simulation closure, reserve system-action capacity, and define deterministic spill ordering and `lastAssigned` updates before acknowledging assignments.

11. **Major — 10 §3.2–§3.4, §15.3; 11 §3.3: sequence and input-generation ownership diverge.** The main thread resumes from `bound.lastSeq`; multiplayer resumes from `acceptedThrough`. During replacement, accepted pending actions may lie above the loaded watermark. Input-generation tracking mentions `release_inputs`, but `player_left` also increments it. **Fix:** specify one allocation/reconciliation algorithm using loaded, accepted and pending watermarks; enumerate every generation-changing system action.

12. **Major — 10 §3.4, §15.4–§15.5: replacement can wait forever for its first packet.** The main thread resends the view after receiving the new worker’s first packet, but extraction requires a view request and no initial request is defined. **Fix:** send generation-tagged view/subscription state after `bound`, or require an unsolicited empty `FULL` packet. Test paused loads and replacements.

13. **Major — 10 §15.4: packet cache retirement is incomplete.** Geometry is removed when its last held chunk leaves, but deleted or repeatedly rebuilt lines can leave obsolete geometry indefinitely while the camera stays still. Overlay removal/reset semantics are absent, and omission semantics for per-frame sections are implicit. **Fix:** declare snapshot versus delta sections, add retirement/reset rules, and test stationary-camera deletion, split/merge, overlay toggling and skipped extraction.

14. **Major — 10 §15.7: renderer/asset indexing and units disagree.** Direction values are 0–15, commonly 0/4/8/12, but the manifest formula treats `d` directly as a dense direction index. Screen coordinates include DPR while the stated sprite scale omits it. Object namespaces also need lookup contracts. **Fix:** provide generated direction-to-frame mappings, one device-pixel placement formula and namespace tables, with calibration fixtures at DPR 1 and 2.

15. **Major — 10 §15.5, §3.3: subscriptions and queries can starve ticks.** Every-packet projections reconstruct and hash records even when unchanged. There are no subscription, result-size or query-work limits; a STATS request can contain 256 keys and two 300-point series each. **Fix:** define supported concurrency and byte/work budgets, share identical projections, use source revisions to avoid needless rebuilding, and schedule expensive queries cooperatively with cancellation.

16. **Major — 10 §4.4, §5.18, §11: deterministic worldgen can still destroy catch-up performance.** Inline generation costs 1–2 ms per chunk, with requests sharing commit ticks and no fan-out bound. Lazy regeneration can merely move load cost into the first thermal/rule accesses. A1 did not measure these paths. **Fix:** define deterministic request deduplication/commit order and bounded scheduling; retain cheap metadata for cold chunks. Benchmark moving frontiers, multiple characters, radar bursts and post-load heat access without workers.

17. **Major — 10 §4.6: wake registration and timer safety need stronger rules.** “Exactly one wake source” conflicts with sleepers needing inventory, power and timer notifications. Stale-node dropping does not bound retained nodes. A 10-bit handle generation can repeat after 1,024 slot reuses while an old work timer survives. **Fix:** define bounded registrations, cancellation/reclamation and same-tick scheduling semantics; validate long-lived timers by serial or prevent reuse until old references are reclaimed.

18. **Major — 10 §4.3, §15.2: determinism primitives remain underspecified.** “Murmur3 finalizer chain,” seed hashing and stream IDs do not determine an algorithm. The expression stage promises finite results at every reachable level despite infinite technologies such as `1000*2^L` and POWI’s ±1024 limit. **Fix:** pin RNG algorithms, salts and golden vectors; define operational numeric limits and deterministic exhaustion behavior instead of an impossible validation promise.

19. **Major — 10 §12, §2.3: M0’s exit requires later systems.** R28 requires heat and an agent path; benchmark definitions include trains, circuits and takeoff. Full-data validation also demands formula/effect implementations belonging to later milestones. Consequently “CI green” has no clear M0 meaning. **Fix:** publish an M0 capability manifest, explicit unsupported-operation errors and seam fakes; split future-system scenarios from M0 tests and define actual benchmark sizes and thresholds.

20. **Major — 10 §10.4, §12: verification claims exceed the tests.** D18 motivates full-state comparisons to catch transient divergence, but cross-engine tests compare digest traces and final hashes; join checks sample state every 600 ticks. Native scenarios also invoke a TS-owned `LocalSequencer` without defining its native counterpart. Test commands omit the promised `simcheck` feature. **Fix:** add short adversarial runs comparing every tick’s canonical bytes, specify the native closure driver, and make feature-enabled test commands explicit.

21. **Minor — 10 §12, §15.10: the fake and goldens are insufficient for integration.** The fake omits STATS, although real STATS is an M0 boundary requirement; real packet fixtures arrive only after implementation. **Fix:** ship one frozen M0 prototype set, start save, closure log, expected states/digests, every M0 projection and a compatible tiny atlas before parallel work. Include negative-coordinate and malformed-input fixtures.

22. **Minor — 10 §12: foundation work includes premature machinery.** General migrations, full-game registries, broad tooling and rigid allocation bans enlarge the serial schema/sim critical path before the first integrated chest works. **Fix:** preserve the binding seams, but implement M0-sized codecs and adapters first; defer unused migrations and tooling. Apply allocation gates to measured steady-state paths with explicit growth exceptions.

Now: M0 is not ready for independent parallel implementation.  
After fixes: yes, once the schema, fake and golden integration set pass a shared contract gate.  
Scope: keep M0 focused on closures, chests, projections, deterministic saves and worker replacement.
